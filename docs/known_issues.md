## 已知问题

### YAML 里不认识的字段会被静默忽略

**现象**：在 `src/data/*.yaml` 里写了页面不支持的字段，或者字段名拼错（例如把 `avatar` 写成 `avater`），构建照常通过，页面上缺了这部分内容，但不会报错。

如果这个字段的值是图片路径，图片还会被当成「已引用」导入，原图被原样发布到 `dist/`，而页面上并不显示它。

**复现**（2026-09-23 验证）：在 `quotes.yaml` 的金句下面加一行 `avatar: head/Portrait(古明地道战).jpg`，然后运行 `npm run build`。构建成功，页面上没有这个头像，但 `dist/_astro/` 里多了 `Portrait(古明地道战).*.jpg` 这张原图。

**原因**：

- `src/lib/content.ts` 用的 zod `z.object()` 默认会丢掉未定义的字段，不报错。
- `src/integrations/pictures.mjs` 会导入 YAML 里所有以图片扩展名结尾的字符串，不区分字段是否被页面使用。
- 被导入、但没有经过 Astro 图片压缩流程的图片，会以原图形式输出。

同一个原因也会吞掉花括号写法里的英文逗号：`{ tagline: 画下的, 写下的 }` 会被读成 `tagline: 画下的` 加一个多余的字段 `写下的`，页面上只剩「画下的」，也不报错。改成严格校验后，这种情况同样会报错。

**影响**：比较小。

- `Pictures/` 已经提交到公开仓库，多发布一份原图不会泄露什么，只是多占空间。
- 主要问题是写错字段时没有提示，维护的人不容易发现错在哪。

**修法**（约十几行）：把 `content.ts` 里的 `z.object()` 换成 `z.strictObject()`。这样出现未定义的字段时，构建会直接失败，并报出「第几项 → 哪个字段：不认识的字段」。改完后用上面的复现步骤验证：构建应该失败，并给出明确提示。

**什么时候修**：等有不熟悉 YAML 的群友开始维护内容时再修，或者在给数据加新字段时顺手一起改。
